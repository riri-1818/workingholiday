## ヘッドレスChromeで実際に検証・バグ修正(2026-08-31 第4回)

curlのステータスコード確認だけでは「動いているように見えて実際は動いていない」バグを見逃すことが判明したため、**ローカルのGoogle ChromeをCDP(DevTools Protocol)経由でスクリプト操作し、実際にスクロール・クリック・ページ内の状態を確認する**方式に切り替えた。

**確認した結果、本当に壊れていたもの(修正済み):**
- ヒーローの粒子ネットワークcanvas: `mix-blend-mode: screen`が明るい背景の上では粒子をほぼ透明にしてしまっていた(ピクセル自体は描画されていたが見えない状態)。blendモードを`normal`にし、色をブランドカラーに変更して解決
- 記事の追従ミニCTAバー: 「アフィリエイトボックスを過ぎたら表示」と「フッター付近では隠す」のしきい値が、通常の記事の長さだと数学的に両立不可能な範囲になっており、**絶対に表示されない設計ミス**だった。固定ピクセルのマージン計算をやめ、ボックスとフッターの実際の画面上の位置(`getBoundingClientRect()`)をリアルタイムに見る方式に変更して解決

**確認した結果、実際は正常に動いていたもの(誤検知だったもの):**
- ダークモード切り替え: 一見動いていないように見えたのは、`body`に付けた0.3秒のCSSトランジション中に確認していたため。0.6秒待つと正しく切り替わることを確認
- スクロールレール・TOCハイライト・トップへ戻るボタン・読了プログレスバー・カバー画像のワイプ・見出し下線・カードの3Dチルト・見出しスクランブル・ティッカー: いずれもDOM状態・ピクセル状態を直接確認し、正常動作を確認済み

## 修正・立体感の強化(2026-08-31 第2回)

- **不具合修正**: スクロールフェードイン演出が「JSが動く前提で要素を透明にする」設計だったため、判定条件によっては要素が表示されないまま固まるリスクがあった。判定式をシンプルな座標比較に変更し、**2秒後には強制的に全部表示するフェイルセーフ**を追加。また各機能を`try/catch`で個別に保護し、1つが失敗しても他の機能・記事本文の表示に影響しない構成に変更
- **立体感**: カード(カテゴリ・記事一覧・ランキング)にマウス位置追従の3Dチルト効果を追加(PC・マウス環境のみ、タッチ端末では無効)。影を多層のアンビエントシャドウに変更してより立体的に
- **動き**: トップページのヒーロー写真にスクール連動のパララックス、統計バッジに数字のカウントアップ演出を追加
- **AI生成っぽさを消す工夫**: ページ全体にごく薄い紙のような粒子質感(grain texture)を重ねてのっぺり感を軽減。バッジ類に微妙な傾き(手作り感)、テキスト選択色・スクロールバーの見た目もブランドカラーに統一
